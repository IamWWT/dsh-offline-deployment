> 回答三个问题：①"打开配置文件"修复原理（是否挂载宿主机桌面）；
> ②点击后为何"无反馈"；③插件源码/编译/加载如何实现。

## 1. 插件源码结构

```
app/dsh-troubleshoot-assistant/
├── src/
│   ├── index.ts        # 插件入口：apply + Config schema + inject
│   ├── tools.ts        # 注册 8 个模型可见工具（status/query_*/evidence/report）
│   ├── settings.ts     # 设置命名空间（数据源动态数组）
│   ├── http.ts         # 数据源 HTTP 调用（安全：超时/字节上限/脱敏）
│   ├── market.ts       # 离线市场目录（dshmarket 端点 + 快照合并）
│   ├── sop.ts          # SOP 提示词（按工作区解析）
│   ├── types.ts        # 类型与常量
│   ├── tools/          # 工具实现（分模块）
│   ├── export.ts       # 导出面
│   └── client/         # 浏览器半（设置卡片 UI）
├── build.mjs           # 构建脚本
├── cordis.patch.yml    # bundle patch（插入插件行）
└── package.json        # 包声明
```

## 2. 编译：build.mjs 产出两半

```bash
cd app/dsh-troubleshoot-assistant && node build.mjs
```

产出到 lib/：

| 产物 | 用途 | 格式 |
|---|---|---|
| lib/index.js | **宿主半**（Node ESM）：插件 apply + 工具 + 设置命名空间 | esbuild bundle，外部化 @deepseek-ai/* |
| lib/client.js | **浏览器半**：设置卡片 | window.__ModuleLoader__.load({...}) factory bundle |
| lib/types/ | TypeScript 声明 | tsc --emitDeclarationOnly |

**宿主半**外部化所有 @deepseek-ai/* 依赖 → 运行时用 profile 的 node_modules（共享依赖身份，避免双模块）。
**浏览器半**是 loader factory：factory(require) => module.exports，外部依赖（react 等）走模块表。

## 3. 加载：三处配合

```
① data/profiles/web/package.json   # bundles 列表声明加载顺序
   "dsh": { "profile": { "bundles": [..., "@dsh-tools/troubleshoot-assistant", ...] } }

② data/profiles/node_modules/@dsh-tools/troubleshoot-assistant/   # 受保护副本
   ├── lib/            # 编译产物（index.js host + client.js browser）
   ├── package.json    # 包声明
   └── cordis.patch.yml # bundle patch：插入 "troubleshoot-assistant" 行 + 默认 config

③ 受保护机制（不可卸载）
   - 不进 profile 的 dependencies（pnpm 管不到）
   - 放共享 fallback 目录 → dsh plugin remove 报 ERR_PNPM_CANNOT_REMOVE_MISSING_DEPS
   - 从源码同步：cp -r lib package.json cordis.patch.yml → data/profiles/node_modules/@dsh-tools/
```

**Loader 组装**（rc.2）：

```
dsh web --profile web
  → 读取 profile 的 bundles 列表
  → 每个 bundle 解析到 node_modules 里的包
  → 应用 bundle 的 cordis.patch.yml（insert 插件行 + config）
  → Loader 按行加载插件（宿主半 apply + 浏览器半注册 UI）
```

## 4. 更新插件流程

```bash
# 1. 改源码 → 构建
cd app/dsh-troubleshoot-assistant && node build.mjs

# 2. 同步受保护副本
rm -rf data/profiles/node_modules/@dsh-tools/troubleshoot-assistant
mkdir -p data/profiles/node_modules/@dsh-tools/troubleshoot-assistant
cp -r app/dsh-troubleshoot-assistant/lib data/profiles/node_modules/@dsh-tools/troubleshoot-assistant/
cp app/dsh-troubleshoot-assistant/package.json data/profiles/node_modules/@dsh-tools/troubleshoot-assistant/
cp app/dsh-troubleshoot-assistant/cordis.patch.yml data/profiles/node_modules/@dsh-tools/troubleshoot-assistant/

# 3. 重启生效
docker compose restart dsh
```

## 5. 「打开配置文件」修复原理（回答①）

**不是挂载宿主机桌面**。容器内无 GUI（无 xdg-open、无 X server），dsh 检测到
canOpenNativePath() 不可用 → 显示"无法打开配置文件"。

**修复**：在 app/xdg-open 放一个**容器内 xdg-open 兼容脚本**，挂载到容器
/usr/local/bin/xdg-open。点击「打开配置文件」时，脚本把目标文件**复制到工作区**：

```bash
# app/xdg-open（容器内）
cp "$TARGET" /workspace/open-here/settings.yaml   # 固定文件名
echo "- $(date) 打开配置文件 → $DEST" >> /workspace/open-here/OPEN_LOG.md
```

**宿主可访问**：offline/workspace/open-here/settings.yaml

**迁移到服务器完全没问题**：不依赖宿主机桌面，纯容器内操作 + 工作区落盘。

## 6. 点击后"无反馈"（回答②）

点击实际**已成功**（openDocument 返回 200，文件已复制），但 dsh 前端**不显示视觉反馈**
（dsh 对 opened:false 显示错误，对 opened:true 静默）。**改进**：

- 文件固定到 /workspace/open-here/settings.yaml（不重复堆积）
- OPEN_LOG.md 记录每次打开时间与来源
- 打开后到宿主机 workspace/open-here/ 查看文件即可
