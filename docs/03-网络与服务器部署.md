# 03 · 网络与服务器部署（让别的主机访问）

> 默认配置下**本机（localhost）与局域网 IP 都可以访问**。dsh web 只监听容器内
> 127.0.0.1:3080（官方拒绝 `--host 0.0.0.0`，防远程代码执行暴露），由 webserver
> config 层 `host: 0.0.0.0` 覆盖为容器内全接口监听，docker 端口映射控制对外暴露。

---

## 1. 默认行为（开箱即用）

```yaml
ports:
  - "${DSH_PUBLIC_PORT:-0.0.0.0:9488}:3080"
```

默认 `0.0.0.0:9488`：本机与局域网都可访问。

## 3. crypto.randomUUID polyfill（关键修复）

`crypto.randomUUID` 仅 secure context（HTTPS/localhost）可用。LAN 通过
`http://<IP>` 访问时浏览器不提供，导致 Agent 预设/插件配置/工作区抛
`crypto.randomUUID is not a function`。

已在前端入口 `runtime/apps/web/dist/index.html` 注入 polyfill：

```html
<script>
  // 用 crypto.getRandomValues（所有上下文可用）实现 UUID v4
  if (typeof crypto.randomUUID !== "function") {
    crypto.randomUUID = function () { /* UUID v4 via getRandomValues */ };
  }
</script>
```

> 重新构建 runtime 后需重新注入（见 [04-开发容器环境源码部署打包.md](04-开发容器环境源码部署打包.md)）。

## 4. 模型/凭据配置为何 LAN 不可用（安全设计）

`credentials.*`、`settings.*` 属于 dsh 的 **PRIVILEGED_METHODS**——
`isTrustedApiRequest(request, [])` 仅放行 loopback。这是**故意的安全护栏**：
防止局域网内任意设备读取/修改配置与凭据。

LAN 用户可正常使用会话、Agent、插件市场；**配置管理请走 localhost**
（或 SSH 端口转发：`ssh -L 9488:127.0.0.1:9488 user@server`）。

## 5. 仅本机访问（收紧）

```bash
echo "DSH_PUBLIC_PORT=127.0.0.1:9488" >> .env
docker compose up -d
```

## 6. 自定义端口 / 防火墙 / TLS

```bash
# 用 8080 端口对外
echo "DSH_PUBLIC_PORT=0.0.0.0:8080" >> .env

# 防火墙放行
#   ufw allow 9488/tcp   或 安全组放行

# TLS：前面加 Caddy/Nginx 反代终止 HTTPS，转发到 127.0.0.1:9488
#   公网部署建议：反代加 Basic Auth / IP 白名单，或仅 VPN 内网
```

## 7. 验证

```bash
curl http://localhost:9488/
curl http://192.168.0.127:9488/
ss -tlnp | grep 9488   # 应为 0.0.0.0:9488
```
