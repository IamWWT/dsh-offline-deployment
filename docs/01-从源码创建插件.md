# 01 · 如何从源码创建一个 dsh 插件

> 本文以本仓库的「故障排查助手」（`@dsh-tools/troubleshoot-assistant`）为范例，
> 演示从零创建一个 DeepSeek Harness 插件。核心参考：
> 《DeepSeek Harness 插件开发与发布复盘》的设计原则——**万物皆插件、
> 配置消除硬编码、lib/ 产物入库、dsh.bundle 声明、git tag 固定版本**。

---

## 1. 插件是什么

dsh 的插件 = 一个导出 `apply(ctx, config)` 函数的 TypeScript 模块：
- **模型适配器、工具注册表、会话日志、甚至 Agent 主循环**都是可替换的插件
- 插件通过 `ctx` 注册能力（工具、设置命名空间、Web 路由、客户端 UI 槽位）
- 配置用 **Schemastery** 定义（类型、默认值、校验）

```
src/
  index.ts          # 插件入口：apply + Config schema + inject
  tools.ts          # 注册模型可见工具
  settings.ts       # 设置命名空间（Web 设置页卡片）
  http.ts           # 数据源 HTTP 调用（安全）
  types.ts          # 类型与常量
  client/           # 浏览器半（设置卡片 UI）
build.mjs           # 构建脚本（esbuild host ESM + client factory bundle + tsc 类型）
package.json        # 包声明（含 dsh.bundle）
cordis.patch.yml    # bundle patch（插入插件行）
```

## 2. 最小插件（greet 工具）

```typescript
// src/index.ts
import type { Context } from '@deepseek-ai/cordis'
import { defineTool } from '@deepseek-ai/dsh-tools'
import z from '@deepseek-ai/schemastery'

export const name = 'my-greet'

export interface Config {
  /** 欢迎语；凡是两个部署可能想要不同的值，都必须是配置字段 */
  greeting: string
}

export const Config: z<Config> = z.object({
  greeting: z.string().default('Hello'),
})

export const inject = ['tools']

export function apply(ctx: Context, config: Config): void {
  ctx.tools.register(defineTool({
    name: 'greet',
    description: '向用户打招呼',
    parameters: { name: { type: 'string', required: true, description: '名字' } },
    output: {
      schema: { type: 'object', additionalProperties: false, properties: { text: { type: 'string' } } },
      render: (_args, value) => [{ type: 'text', text: (value as { text: string }).text }],
    },
    async execute(args) {
      return { text: `${config.greeting}, ${args.name}!` }
    },
  }))
}
```

## 3. 配置化（告别硬编码）

设计原则（来自参考文章）：**"凡是两个部署可能想要不同的值，必须是配置字段"**。

```typescript
export const Config: z<Config> = z.object({
  greeting: z.string().default('Hello'),
  timeoutMs: z.number().min(0).max(120000).default(15000),
  // 敏感字段：role('secret') → wire 上自动脱敏
  apiToken: z.string().role('secret').default(''),
})
```

## 4. 注册设置命名空间（Web 卡片）

用 `installSettingsSection` 让用户在设置页配置（见 `src/settings.ts`）：

```typescript
import { settingsNamespace } from '@deepseek-ai/dsh-settings'
import { installSettingsSection } from '@deepseek-ai/dsh-settings'

const NAMESPACE = settingsNamespace('troubleshoot')
installSettingsSection(ctx, NAMESPACE, Schema, emptySettings, {
  setSource: (current) => { source = current },   // 热更新：工具调用时读最新值
})
```

## 5. 浏览器半（客户端插件）

设置卡片通过 `settings.plugin.item` 槽位注入（见 `src/client/`）：

```typescript
// src/client/index.ts
import type { ClientContext } from '@deepseek-ai/dsh-client-runtime/client'
export const inject = ['slots', 'settingsScope']
export function apply(ctx: ClientContext): void {
  ctx.slots.inject('settings.plugin.item', () => ctx.slots.register({
    name: 'settings.plugin.item',
    key: 'troubleshoot',
    inject: () => controller.inject(),
  }, TroubleshootCard))
}
```

## 6. 本地验证

```bash
# 1. 构建（lib/ 产物）
node build.mjs

# 2. 放入 profile 的受保护副本（不可卸载路径）
mkdir -p data/profiles/node_modules/@dsh-tools/my-plugin
cp -r lib package.json cordis.patch.yml data/profiles/node_modules/@dsh-tools/my-plugin/

# 3. 挂载到 profile bundles（data/profiles/web/package.json）
#    "dsh": { "profile": { "bundles": [..., "@dsh-tools/my-plugin"] } }

# 4. 重启容器验证
docker compose restart dsh
docker logs dsh-harness | grep my-plugin
```

## 7. 开发提示

- `build.mjs` 从 pnpm store 解析 esbuild/tsc（见仓库内构建脚本）
- 宿主半（lib/index.js）外部化所有 `@deepseek-ai/*` 依赖 → 运行时用 profile 的 node_modules
- 浏览器半（lib/client.js）是 `window.__ModuleLoader__.load({...})` factory bundle
- **lib/ 构建产物要提交进仓库**（.gitignore 千万别忽略它）——避免用户端构建
- 敏感值用 `role('secret')` + `env:<NAME>` 引用，机密不落盘

> 完整范例：本仓库 `app/plugins/dsh-troubleshoot-assistant/` 源码。
