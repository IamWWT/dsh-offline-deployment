# 04 · 在开发容器环境中从源码部署与打包本项目

> 本文面向开发者：如何在**带源码的容器环境**里编译、部署、打包本项目
> （deepseek-harness rc.2 + 故障排查助手插件 + 离线市场）。

---

## 1. 环境要求

- Docker（本机需支持目标架构：x86_64 或 aarch64）
- 目标架构镜像：`rocky8-pygojava-wwt_amd64:v20260817` 或 `rocky8-pygojava-wwt_arm64:v20260817`
- 网络（首次构建需拉取 npm 依赖）

## 2. 目录结构

```
offline/
├── deepseek-harness/        # dsh 源码（git 仓库，rc.2）
├── app/                     # 项目材料
│   ├── dsh-troubleshoot-assistant/   # 故障排查助手插件源码
│   └── offline-market/plugins.json   # 离线市场快照
├── data/                    # DSH_HOME（profiles/sessions/settings）
├── workspace/               # 用户空间（默认工作区 + SOP）
├── runtime/                 # 编译产物（PHASE 1 固化）
├── dsh-entry.sh             # 容器入口（build / run）
├── build-runtime.sh         # 预编译脚本（一条 docker 命令）
├── pack.sh                  # 打包脚本（--mode runtime/dev + --arch + --compress）
└── docker-compose.yml       # 生产运行编排（单服务）
```

## 3. 更新源码

```bash
cd deepseek-harness
git pull --ff-only origin master   # 更新到最新
cd ..
```

> 源码更新后需要**重新构建**（见第 5 步）。注意：源码更新可能改变依赖
> 版本（如 esbuild 平台包），若本地构建报错，先清 node_modules 重装：
> `rm -rf node_modules && pnpm install`

## 4. 构建插件（故障排查助手）

```bash
cd app/dsh-troubleshoot-assistant
node build.mjs    # 产出 lib/（host ESM + client bundle + types）
cd ../..

# 同步到受保护副本（不可卸载路径）
rm -rf data/profiles/node_modules/@dsh-tools/troubleshoot-assistant
mkdir -p data/profiles/node_modules/@dsh-tools/troubleshoot-assistant
cp -r app/dsh-troubleshoot-assistant/lib data/profiles/node_modules/@dsh-tools/troubleshoot-assistant/
cp app/dsh-troubleshoot-assistant/package.json data/profiles/node_modules/@dsh-tools/troubleshoot-assistant/
cp app/dsh-troubleshoot-assistant/cordis.patch.yml data/profiles/node_modules/@dsh-tools/troubleshoot-assistant/
```

## 5. 编译 dsh runtime（核心步骤）

`build-runtime.sh` 用一条 docker 命令完成整个编译（install + build + 固化 runtime）：

```bash
# x86_64 开发机
bash build-runtime.sh --arch amd64 --dev

# arm64 开发机（或交叉编译到 arm64 目标）
bash build-runtime.sh --arch arm64 --dev --image rocky8-pygojava-wwt_arm64:v20260817

# 精简模式（--prod，当前与 --dev 等价，因 pnpm prune 对 monorepo 不适用）
bash build-runtime.sh --arch amd64 --prod
```

脚本做的事（等价于）：

```bash
docker run --rm --platform linux/$ARCH \
  -v ./deepseek-harness:/workspace/dsh \
  -v ./runtime:/opt/dsh-runtime \
  -v ./data:/opt/dsh \
  -v ./workspace:/workspace \
  -v ./app:/app \
  -v ./.dsh-state:/opt/dsh-state \
  -v ./dsh-entry.sh:/usr/local/bin/dsh-entry.sh:ro \
  $IMAGE -c "/usr/local/bin/dsh-entry.sh build"
```

## 6. 开发模式下运行验证

```bash
docker compose up -d dsh
docker logs -f dsh-harness    # 观察 deeptutor/troubleshoot 加载、web 启动
docker exec dsh-harness curl -s http://127.0.0.1:3080/api/dshmarket/plugins.json | head -c 100
```

## 7. 打包

```bash
# runtime 模式（精简直跑，不含源码）—— 交付用
rm -f dsh-offline-*.tar.*
./pack.sh --mode runtime --arch amd64 --compress gzip

# dev 模式（含源码）—— 开发/调试用
./pack.sh --mode dev --arch amd64

# xz 压缩更小（慢）
./pack.sh --mode runtime --arch arm64 --compress xz
```

## 8. 常见问题

| 现象 | 处理 |
|---|---|
| 构建报 esbuild platform 错误 | 源码更新后混入异架构 esbuild；`rm -rf node_modules && pnpm install` |
| 打包后全新解压启动报 cordis 找不到 | 检查 `pack.sh` 的 `--anchored` 排除是否生效（防止误删 runtime 内部 node_modules） |
| arm64 打包体积大 | dsh 是 245 包 monorepo，node_modules 即运行时本体；用 `--compress xz` 减小 |
| 容器一直 restart | `docker logs dsh-harness` 看错误；多数是 runtime 缺失或架构不匹配 |
