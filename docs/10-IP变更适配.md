# 10 · IP 变更适配手册

> 面向：运维。解决：部署机器换了 IP / 网络（如从开发机迁到内网、DHCP 地址变化）时，
> 如何改配置让 dsh 继续可用。核心原则：**IP 只在一个地方改，其余自动跟随**。

---

## 0. IP 出现在哪些地方（为什么会有多处）

| 位置 | 作用 | 变更影响 |
|---|---|---|
| `.env` 的 `DSH_TRUSTED_HOSTS` | ★ **唯一需要手工改的**：compose 注入容器的 LAN 信任围栏 | 决定 LAN 能否做配置管理 |
| `runtime/apps/web/dist/index.html` 的 `__DSH_TRUSTED_HOSTS__` | 前端 isLoopback/信任判定 | 由 apply 脚本注入，**重跑脚本自动更新** |
| `runtime/packages/bundle/web-app/cordis.patch.yml` | 后端 API 信任 | 同上，自动更新 |
| `data/settings.yaml` 的模型/数据源 URL | 本地模型 `baseURL`、Prometheus 等数据源地址 | **业务配置，手工改**（见第 3 节） |

## 1. 标准换 IP 流程（推荐，只改 .env）

```bash
# 1) 改 .env 里的 DSH_TRUSTED_HOSTS 为新 IP
vim .env   # DSH_TRUSTED_HOSTS=192.168.1.50

# 2) 重跑运行时修复（自动从 .env 读取新 IP，注入 index.html 和 web-app patch）
bash scripts/apply-runtime-fixes.sh

# 3) 重启容器
docker compose up -d

# 4) 验证（L3：浏览器真实访问）
node scripts/verify-open-document.cjs http://<新IP>:9488
```

> apply-runtime-fixes.sh 的 IP 解析顺序：命令行参数 > .env 的 DSH_TRUSTED_HOSTS（取第一个）> 默认值。
> 不想改 .env 也可直接传参：`bash scripts/apply-runtime-fixes.sh 192.168.1.50`。

## 2. 若同时改对外端口

```bash
# .env 加：
DSH_PUBLIC_PORT=0.0.0.0:9488   # 宿主端口 → 容器 3080；0.0.0.0=对所有网卡开放

# 改完 docker compose up -d 生效（docker-proxy 重新映射）
```

## 3. settings.yaml 里的模型/数据源地址

本地模型或数据源可能指向另一台机器（如 GPU 机 192.168.0.127:8880）。这些是**业务 URL**，
在 WebUI「设置 → 模型配置 / 插件 → 故障排查助手」里改，或直接编辑 `data/settings.yaml`：

```yaml
llm-pi-ai:
  providers:
    local:
      baseURL: http://<模型机IP>:8880/v1   # ← 改成模型实际地址
troubleshoot:
  dataSources:
    - url: http://<监控平台IP>:9440/      # ← 数据源地址
```

> 注意：容器内 `settings.yaml` 在 `/opt/dsh/settings.yaml`（映射宿主 `data/settings.yaml`）；
> 也可在 WebUI「打开配置文件」弹框中直接查看/参考。

## 4. 双网卡 / 多 IP 情况

`DSH_TRUSTED_HOSTS` 支持逗号分隔多个地址，全部信任：

```bash
DSH_TRUSTED_HOSTS=192.168.1.50,10.0.0.8,harness.internal
```

## 5. 常见问题

- **换了 IP 后 settings/模型配置 403 或"unavailable"**：`.env` 的 DSH_TRUSTED_HOSTS 没更新，或忘了重跑 apply-runtime-fixes.sh。
- **浏览器缓存旧 IP**：硬刷新（Ctrl+Shift+R）。
- **LAN 访问不了但本机可以**：`DSH_BIND` 需为 `0.0.0.0`（服务器部署，见 [03-网络与服务器部署.md](03-网络与服务器部署.md)）。
- **Docker 端口没生效**：确认 `DSH_PUBLIC_PORT` 与防火墙放行。

## 6. 为什么这样设计（单一来源）

- 运行时注入（index.html / web-app patch）是**构建产物**，不手工改——由 apply 脚本从 .env 生成；
- 这样换 IP 只动 `.env` 一处，脚本负责把新 IP 刷到所有需要的地方；
- 业务 URL（模型/数据源）本质是"连别的机器"，与"这台机器的地址"是两回事，分开管理。
