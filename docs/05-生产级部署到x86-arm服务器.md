# 05 · 生产级部署到 x86 / ARM 服务器

> 面向运维：把本项目以**生产运行时**部署到目标服务器（x86_64 或 arm64），
> 内网离线、零编译直接运行。

---

## 0. 架构选择（先读）

| 目标服务器 | 构建机（有网络） | 镜像 |
|---|---|---|
| x86_64 | x86_64 机器 | `rocky8-pygojava-wwt_amd64:v20260817` |
| arm64 | arm64 机器（或 qemu 模拟） | `rocky8-pygojava-wwt_arm64:v20260817` |

> **关键**：runtime 里的 node_modules 是架构相关的（原生二进制 node-pty 等）。
> **必须在目标架构的构建机上编译**。x86 构建的 runtime 不能用于 arm64 服务器。

## 1. 三步总览

```
① 构建机（有网络）: build-runtime.sh 编译 → ./runtime（目标架构）
② 构建机:           pack.sh --mode runtime 打包（含 runtime，解压即跑）
③ 目标服务器（内网）: 解压 → docker compose up -d → 访问
```

## 2. 构建机操作（一次）

```bash
# ① 编译 runtime（以 arm64 为例；x86 用 --arch amd64）
bash build-runtime.sh --arch arm64 --image rocky8-pygojava-wwt_arm64:v20260817 --dev

# ② 打包（runtime 模式：不含源码，含完整 runtime）
rm -f dsh-offline-*.tar.*
./pack.sh --mode runtime --arch arm64 --compress gzip
# 产物：dsh-offline-<时间戳>.tar.gz（约 700MB，含 arm64 runtime）
```

> 若构建机是 x86_64 但要出 arm64 包：先注册 qemu 模拟，再跑 arm64 镜像构建：
> `docker run --privileged --rm tonistiigi/binfmt --install arm64`

## 3. 拷贝到目标服务器

```bash
scp dsh-offline-*.tar.gz user@server:/opt/dsh-offline/
```

## 4. 目标服务器部署（内网，零编译）

```bash
cd /opt/dsh-offline

# 解压（保持 uid 1000，与容器内 appuser 一致）
tar -xzf dsh-offline-*.tar.gz
sudo chown -R 1000:1000 .   # 若以 root 解压

# 检查 .env（包内已内置对应架构镜像标签）
grep DSH_IMAGE .env
#   应为 rocky8-pygojava-wwt_<arch>:<版本>

# 启动（无需 PHASE 1 / 无需 npm / 无需编译）
docker compose up -d

# 访问
#   本机:  http://127.0.0.1:9488
#   局域网: 见 docs/03（设 DSH_BIND=0.0.0.0）
```

## 5. 服务器模式（供别人访问）

```bash
# 允许局域网访问
echo "DSH_BIND=0.0.0.0" >> .env
# 自定义端口（可选）
echo "DSH_PUBLIC_PORT=0.0.0.0:9488" >> .env
docker compose up -d

# 防火墙放行
#   ufw allow 9488/tcp   或 安全组放行
```

详细见 [03-网络与服务器部署.md](03-网络与服务器部署.md)。

## 6. 生产运维要点

- **数据持久化**：`./data`（DSH_HOME）、`./workspace`、`./app` 都是宿主机卷，备份这三个目录即可
- **日志**：`docker logs -f dsh-harness`；长期用 `docker logs --until` 或接日志采集
- **更新**：日常更新 = 构建机 `git pull` → `build-runtime.sh` → `pack.sh` → 拷包 → 目标机解压替换 → `docker compose up -d`
- **健康检查**：compose 已含 healthcheck；`docker ps` 看 (healthy)
- **TLS**：生产建议 Caddy/Nginx 反代终止 HTTPS，见 docs/03
- **凭据**：`.env` 内含 LLM API Key 等，妥善保管；机密用 `env:<NAME>` 引用不落盘

## 7. 架构迁移（amd64 → arm64）

```bash
# 在 arm64 构建机：
bash build-runtime.sh --arch arm64 --image <arm64镜像> --dev   # 编译 arm64 runtime
./pack.sh --mode runtime --arch arm64                         # 打 arm64 包
# 拷贝到 arm64 目标机解压 up -d
```

> 迁移时 `data/`（profile node_modules）会被 PHASE 1 自动按新架构重建（node-pty 等原生模块）。
